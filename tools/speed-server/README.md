# pw-speed-server

The speed-test server that XeroHost deploys on its nodes (Miami, Dallas, São Paulo, ...) and that anyone can run
as a *custom server* in PacketWard. A small axum/hyper service: it generates download data in memory, throws
uploads away, answers pings and tells each client its own public IP. No files, no database, no telemetry, no
outbound connections.

License: PolyForm Shield 1.0.0 (part of the PacketWard repository).

## Endpoints

| Endpoint | Description |
|---|---|
| `GET /ping` | `{"ts_ms": <server unix time in ms>}`, a few dozen bytes, no caching. Use it for latency and jitter. |
| `GET /download?bytes=N` | Streams exactly `N` generated bytes with `Content-Length` (`application/octet-stream`, `Cache-Control: no-store`). Data is pseudo-random from a pool generated once at startup and re-sliced, so it costs no CPU, never touches disk and uses constant memory for any `N` (up to `limits.max_download_bytes`, default 50 GiB). Generation stops immediately when the client disconnects. |
| `POST /upload` | Reads the body as a stream and discards it. Returns `{"bytes": <received>, "millis": <server-side duration>}`. Chunked bodies are accepted. |
| `GET /info` | Node id, name, location, version, max sizes, limits, and **`client_ip`**: the requesting client's public IP as this server sees it. PacketWard uses it to show the user's source IP (no third-party lookup). |
| `GET /healthz` | `200 ok`. Not rate limited; use it for load-balancer/orchestrator probes. |

Optional query parameter on `/download` and `/upload`: `test=<id>` (1-64 chars of `A-Za-z0-9_-`), see
[Concurrency model](#concurrency-model). Unknown query parameters (cache busters like `r=0.123`) are ignored.

Example `/info` response:

```json
{
  "protocol": 1,
  "server_version": "0.1.0",
  "node_id": "mia",
  "node_name": "Miami",
  "location": "Miami, US",
  "client_ip": "203.0.113.9",
  "max_download_bytes": 53687091200,
  "max_upload_bytes": 10737418240,
  "limits": {
    "max_concurrent_tests_per_ip": 2,
    "max_streams_per_test": 8,
    "max_concurrent_tests_global": 64,
    "requests_per_minute_per_ip": 600,
    "hourly_bytes_per_ip": 107374182400,
    "daily_bytes_per_ip": 322122547200,
    "max_transfer_secs": 14400
  }
}
```

### Status codes

| Code | When |
|---|---|
| 200 | OK |
| 400 | `bytes` missing, `0`, negative, non-numeric, not plain digits, overflowing `u64`, larger than `max_download_bytes`, given twice; invalid `test` id |
| 408 | A transfer ran past `server.max_transfer_secs` |
| 413 | Upload larger than `limits.max_upload_bytes` (declared `Content-Length` is checked before reading anything; chunked uploads are cut as soon as the total crosses the limit) |
| 429 | A protection limit was hit; always carries `Retry-After` (seconds) |

Errors are small JSON documents: `{"error": "too_many_requests", "message": "..."}`.

## Quick start

```bash
# from the repository root
cargo run -p pw-speed-server -- --print-default-config > speed.toml   # edit it
cargo run --release -p pw-speed-server -- --config speed.toml
curl http://127.0.0.1:8080/info
curl -o /dev/null -w '%{speed_download} B/s\n' 'http://127.0.0.1:8080/download?bytes=104857600'
```

Plain HTTP on `127.0.0.1:8080` is the default so a local test needs no certificates. **In production use TLS**
(reverse proxy or the built-in rustls listener, below).

## Configuration

Precedence, lowest to highest: built-in defaults < TOML file (`--config` / `PW_SPEED_CONFIG`) <
`PW_SPEED_*` environment variables < command-line flags. Unknown keys in the file are an error. The server
validates everything at startup and refuses to run with an inconsistent configuration;
`pw-speed-server --check-config` validates without starting.

`pw-speed-server --print-default-config` prints the fully commented default file. Byte values are in bytes
(`1 GiB = 1073741824`); **`0` means unlimited** for every limit where it is noted.

| TOML key | Env var | Default | Meaning |
|---|---|---|---|
| `node.id` | `PW_SPEED_NODE_ID` | `local` | Stable id (`a-z0-9-_`, max 32). Must equal the `id` in `nodes.json`. |
| `node.name` | `PW_SPEED_NODE_NAME` | `Local speed node` | Display name shown in `/info`. |
| `node.location` | `PW_SPEED_NODE_LOCATION` | empty | Free text, e.g. `Miami, US`. |
| `server.listen` | `PW_SPEED_LISTEN` | `127.0.0.1:8080` | Listen address. |
| `server.header_read_timeout_secs` | `..._HEADER_READ_TIMEOUT_SECS` | 10 | Time allowed to send request headers (slow-loris defense); also bounds the TLS handshake. |
| `server.idle_timeout_secs` | `..._IDLE_TIMEOUT_SECS` | 30 | A connection with no bytes moving in either direction for this long is closed (idle keep-alive, stalled reader/writer). Healthy transfers never trip it. |
| `server.max_transfer_secs` | `..._MAX_TRANSFER_SECS` | 14400 | Hard cap on one download/upload. |
| `server.max_connections` | `..._MAX_CONNECTIONS` | 2048 | Open connections; extra ones wait in the kernel backlog. |
| `server.max_connections_per_ip` | `..._MAX_CONNECTIONS_PER_IP` | 128 | `0` = unlimited. Not applied to trusted reverse proxies. |
| `server.shutdown_grace_secs` | `..._SHUTDOWN_GRACE_SECS` | 10 | On SIGTERM/Ctrl-C, in-flight transfers get this long. |
| `tls.cert_file`, `tls.key_file` | `PW_SPEED_TLS_CERT_FILE`, `..._KEY_FILE` | unset | PEM chain and key. Both or neither. Needs a binary built with `--features tls` (the Docker image has it). |
| `limits.max_download_bytes` | `..._MAX_DOWNLOAD_BYTES` | 53687091200 (50 GiB) | Largest `bytes=`. |
| `limits.max_upload_bytes` | `..._MAX_UPLOAD_BYTES` | 10737418240 (10 GiB) | Largest upload body. |
| `limits.max_concurrent_tests_per_ip` | `..._MAX_TESTS_PER_IP` | 2 | `0` = unlimited. |
| `limits.max_streams_per_test` | `..._MAX_STREAMS_PER_TEST` | 8 | Parallel streams inside one test. |
| `limits.max_concurrent_tests_global` | `..._MAX_TESTS_GLOBAL` | 64 | `0` = unlimited. |
| `limits.requests_per_minute_per_ip` | `..._REQUESTS_PER_MINUTE` | 600 | Token bucket (burst = the same number); `0` = unlimited. |
| `limits.hourly_bytes_per_ip` | `..._HOURLY_BYTES_PER_IP` | 107374182400 (100 GiB) | `0` = unlimited. |
| `limits.daily_bytes_per_ip` | `..._DAILY_BYTES_PER_IP` | 322122547200 (300 GiB) | `0` = unlimited. |
| `proxy.trust_header` | `..._PROXY_TRUST_HEADER` | `false` | See [Client IP and reverse proxies](#client-ip-and-reverse-proxies). |
| `proxy.header` | `..._PROXY_HEADER` | `X-Forwarded-For` | |
| `proxy.trusted_peers` | `..._PROXY_TRUSTED_PEERS` (comma list) | `127.0.0.0/8`, `::1/128` | CIDRs of reverse proxies. |
| `logging.level` | `..._LOG_LEVEL` | `info` | `tracing` filter. |
| `logging.format` | `..._LOG_FORMAT` | `text` | `text` or `json`. |
| `logging.log_full_ips` | `..._LOG_FULL_IPS` | `false` | See [Logging and privacy](#logging-and-privacy). |

(`...` = `PW_SPEED`.) Command-line flags: `--config`, `--listen`, `--node-id`, `--node-name`, `--location`,
`--log-level`, `--print-default-config`, `--check-config`.

Validation rules worth knowing: `hourly_bytes_per_ip` and `daily_bytes_per_ip`, when not 0, must be at least
`max_download_bytes` (otherwise the largest bin test could never run) and the hourly value may not exceed the
daily one.

## Concurrency model

PacketWard runs its download/upload tests with 4-8 parallel streams, but a single client must not be able to
hold many tests open. The server therefore limits **tests**, not raw requests:

* A *stream* is one `/download` or `/upload` request.
* A *test* is the set of streams from one client IP that carry the same `?test=<id>` (PacketWard should send
  one random id per run). A stream without an id is a test of its own.
* Limits: `max_concurrent_tests_per_ip` (default 2, e.g. one download test plus one upload test),
  `max_streams_per_test` (default 8) and `max_concurrent_tests_global` (default 64).

Byte budgets (`hourly_bytes_per_ip`, `daily_bytes_per_ip`) are charged **up front for the requested size** of a
download and refunded for whatever was not sent when the connection ends, so cancelled tests do not burn the
budget. Uploads are charged as they arrive. A client planning a 50 GiB test split over 8 streams must make sure
the sum of the `bytes` values fits the remaining budget; `/info` publishes the limits.

IPv6 clients are limited per /64 (one host owning a whole /64 would otherwise multiply its quotas).
State is in memory only, bounded (idle clients are swept, at most 100 000 tracked) and reset on restart.

## Client IP and reverse proxies

`/info.client_ip` and every per-client limit use the *client IP*. By default that is the TCP peer address.
Behind a reverse proxy every client would look like `127.0.0.1`, so enable the header:

```toml
[proxy]
trust_header = true
header = "X-Forwarded-For"
trusted_peers = ["127.0.0.0/8", "::1/128"]   # the proxy's address(es)
```

The header is honored **only** when `trust_header` is true **and** the TCP peer is inside `trusted_peers`;
otherwise it is ignored, so a client talking to the server directly cannot spoof its address. For
`X-Forwarded-For` lists the right-most entry that is not itself a trusted proxy wins (a client-supplied
leftmost value never does). A missing or malformed header falls back to the peer address. Make sure your proxy
*overwrites* the header instead of appending to a client-supplied one (see the nginx example).

## Logging and privacy

Logs use `tracing` (text or JSON, to stderr, so journald/Docker collect them). One info line per finished
download/upload (bytes, duration, whether it completed) and per start/stop. **Client IPs are truncated in logs**
(IPv4 `a.b.c.0/24`, IPv6 `/48`): enough to spot an abusive network, not enough to identify a subscriber. Set
`logging.log_full_ips = true` only if you need it for an abuse investigation and have a legal basis to keep
the data. Nothing is persisted, no telemetry is sent anywhere.

## Deploying on a XeroHost node

### Build

```bash
# native TLS is optional; omit --features tls if you terminate TLS in a reverse proxy
cargo build --release --locked -p pw-speed-server --features tls
install -m 0755 target/release/pw-speed-server /usr/local/bin/
```

Or the container image (build context = repository root, distroless, runs as `nonroot`):

```bash
docker build -f tools/speed-server/Dockerfile -t pw-speed-server .
docker run -d --name speed --restart unless-stopped -p 127.0.0.1:8080:8080 \
  -e PW_SPEED_NODE_ID=mia -e PW_SPEED_NODE_NAME=Miami -e PW_SPEED_NODE_LOCATION="Miami, US" \
  -e PW_SPEED_PROXY_TRUST_HEADER=true \
  pw-speed-server
```

(With Docker's bridge network the proxy reaches the container from the bridge gateway, not from loopback;
add that address, e.g. `-e PW_SPEED_PROXY_TRUSTED_PEERS=172.17.0.0/16`.)

### systemd

`deploy/pw-speed-server.service` is a hardened unit (dedicated user, no capabilities, read-only filesystem,
`RestrictAddressFamilies`). Typical flow:

```bash
useradd --system --no-create-home --shell /usr/sbin/nologin pw-speed
install -d /etc/pw-speed-server
cat >/etc/pw-speed-server/config.toml <<'EOF'
[node]
id = "mia"                  # same id as in nodes.json
name = "Miami"
location = "Miami, US"

[server]
listen = "127.0.0.1:8080"   # behind the reverse proxy; use 0.0.0.0:443 + [tls] for native TLS

[proxy]
trust_header = true         # only when a reverse proxy sets X-Forwarded-For
EOF
install -m 0644 tools/speed-server/deploy/pw-speed-server.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now pw-speed-server
journalctl -u pw-speed-server -f
```

Set the node name and location in `[node]` (or `PW_SPEED_NODE_*` / `--node-name` / `--location`). `systemctl stop`
sends SIGTERM: the listener closes, idle connections drop, running transfers get `shutdown_grace_secs` to finish.

### TLS and reverse proxy

Plain HTTP is for local testing only. In production either:

1. **Reverse proxy (recommended).** nginx example, proxy and server on the same host:

   ```nginx
   server {
       listen 443 ssl http2;
       server_name REPLACE-WITH-REAL-HOSTNAME;
       ssl_certificate     /etc/letsencrypt/live/REPLACE-WITH-REAL-HOSTNAME/fullchain.pem;
       ssl_certificate_key /etc/letsencrypt/live/REPLACE-WITH-REAL-HOSTNAME/privkey.pem;

       location / {
           proxy_pass http://127.0.0.1:8080;
           proxy_http_version 1.1;
           proxy_set_header Connection "";
           proxy_set_header Host $host;
           proxy_set_header X-Forwarded-For $remote_addr;   # overwrite, never append client input

           # A speed test must stream, not buffer, and must not be cut early.
           proxy_buffering off;
           proxy_request_buffering off;
           client_max_body_size 0;               # the server enforces max_upload_bytes itself
           proxy_read_timeout 4h;
           proxy_send_timeout 4h;
           gzip off;
       }
   }
   ```

   Caddy: `reverse_proxy 127.0.0.1:8080 { flush_interval -1 }` (Caddy sets `X-Forwarded-For` itself and
   streams without request-size limits by default). **Do not put the node behind a CDN or caching/WAF proxy**
   (for example Cloudflare's proxied mode): they buffer, cap body sizes and would measure the CDN, not the
   link. Point the DNS record straight at the node.

2. **Native TLS** (`--features tls`): set `[tls] cert_file`/`key_file`, `listen = "0.0.0.0:443"`, and give the
   service `AmbientCapabilities=CAP_NET_BIND_SERVICE` (see the commented lines in the unit). HTTP/1.1 only.
   The service user must be able to read the key (Let's Encrypt `privkey.pem` is root-only by default): use
   group permissions on a copy/deploy hook, or systemd `LoadCredential=` and point `[tls]` at
   `/run/credentials/pw-speed-server.service/...`. The certificate is read once at start; restart after renewal (e.g. a certbot `--deploy-hook "systemctl
   restart pw-speed-server"`).

### Firewall and ports

Open **only the public listener**, TCP, nothing else (the server uses no UDP and makes no outbound
connections):

```bash
ufw allow 443/tcp           # reverse proxy or native TLS
# nothing for 8080 when it is bound to 127.0.0.1
# firewalld: firewall-cmd --permanent --add-service=https && firewall-cmd --reload
# nftables:  tcp dport 443 accept
```

Capacity planning: a node can serve at most `max_concurrent_tests_global x max_streams_per_test` simultaneous
streams. Per-IP byte budgets cap what one client can pull per hour/day; tune them to the node's transfer
allowance. Raise `net.core.somaxconn` and `LimitNOFILE` on very busy nodes.

### Telling PacketWard about the node (`nodes.json`)

PacketWard does not hard-code XeroHost nodes. It fetches `nodes.json` from the public
`XeroHost/packetward-blocklist` repository and caches it. After a node is deployed and reachable, add it:

```json
{
  "version": 1,
  "nodes": [
    { "id": "mia", "name": "Miami",     "host": "REPLACE-WITH-REAL-HOSTNAME", "port": 443 },
    { "id": "dal", "name": "Dallas",    "host": "REPLACE-WITH-REAL-HOSTNAME", "port": 443 },
    { "id": "sao", "name": "São Paulo", "host": "REPLACE-WITH-REAL-HOSTNAME", "port": 443 }
  ]
}
```

`id` must equal the node's `node.id`, `host` is the DNS name that carries the TLS certificate, `port` the
public port. The file carries no URL scheme: production nodes are expected to serve HTTPS on the listed port
(plain HTTP is for custom servers on a LAN or loopback). Verify a node before listing it:

```bash
curl -s https://HOST:PORT/info | jq .
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' 'https://HOST:PORT/download?bytes=1000000'
```

Users can also add any server running this program as a custom server in PacketWard's Speed Test page.

## Development

```bash
cargo test -p pw-speed-server                      # unit + loopback integration tests (port 0, <= 64 MB each)
cargo test -p pw-speed-server --features tls       # also the TLS tests (needs a C compiler for ring)
cargo clippy -p pw-speed-server --all-targets -- -D warnings
# benchmarks (each moves at most 64 MB):
cargo test --release -p pw-speed-server --lib -- --ignored --nocapture
cargo test --release -p pw-speed-server --test api -- --ignored --nocapture --test-threads=1
```

`tests/fixtures/test-{cert,key}.pem` is a throwaway self-signed certificate (CN=localhost, valid 100 years)
used only by the TLS tests. Its key protects nothing; never reuse it.

Layout: `config.rs` (TOML/env/CLI + validation), `ip.rs` (CIDR, trusted-proxy resolution, log truncation),
`limits.rs` (rate/concurrency/budget limiter, time injected for tests), `payload.rs` (generated body),
`io.rs` (idle-timeout wrapper), `app.rs` (router and endpoints), `server.rs` (listener, TLS, graceful shutdown).

Not implemented on purpose: HTTP/2 or HTTP/3 (a speed test wants one TCP stream per stream), CORS (PacketWard
is a native client), Windows service hosting (Linux nodes only; it runs on Windows for development).
